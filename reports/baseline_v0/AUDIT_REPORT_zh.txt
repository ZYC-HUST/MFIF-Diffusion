Mask-DiFuser / COME-MFIF 首轮从零训练审计
日期：2026-11-20

结论
====
训练—保存—恢复—推理—评估的工程链路基本可用；现有权重和官方采样组合尚不能作为
效果可靠、可直接承载论文改进结论的正式 MFIF 基线。应保留为 baseline-v0。
主要问题是颜色/亮度偏移、后期 PSNR 波动和训练日程尚未有效收尾，并非任务完全没有学到。
本次只新增独立审计脚本和输出；未改动官方算法源码、原实验结果或已有权重，也未启动新训练。

1. 完成情况与训练日程
====================
2026-11-19 22:22:51 左右开始，11-20 09:00:15 完成训练，09:04:44 完成自动评估（北京时间）。
训练、评估退出码均为 0；仅一次启动，无异常恢复记录。日志未见 OOM、NaN、NCCL 错误。
全部 1252 条训练日志中的数值有限，进行了 64 次固定子集验证。
最终步数 31247，总样本访问次数 999904，约 9.08 次完整数据量；不是 1249 次遍历 MFIF 数据。
停止由预设时间触发；配置上限为 87500 步，本轮完成约 35.7%，不是由收敛判据停止。

调度 epoch 是沿官方 DIV2K 推荐设置折算的单位：800/(4*8)=25 次更新。
实际数据 epoch 与调度 epoch 分开记录。前 5000 步只启用噪声损失；第 5001 步启用辅助损失。
5000 步附近损失跳变与目标切换一致，不能单凭这次跳变认定训练崩溃。
官方学习率热身被映射到 25000 步，约占本轮 80%；终点学习率约 9.985e-5，仍接近峰值 1e-4。
因此本轮基本没有经历充分的降学习率收尾，不能据此宣布收敛。

最终噪声 MSE 约 0.00147，说明噪声预测在学习，不等于最终融合已准确。
训练噪声目标、随机时间步的单步重建、从噪声开始的五步采样是不同评价对象。
后期训练总损失仍在下降，但验证 PSNR 波动，不能只按训练 loss 判断可用性或过拟合。

2. 工程与数据审计
================
当前和实验快照中的 Diffusion/model.py、Diffusion/diffusion.py、loss/Myloss.py、Scheduler.py
逐字节等于本地官方 Git HEAD。融合网络为随机初始化；冻结的 LPIPS/VGG 仅用于原有感知损失。
正式训练没有接续 pilot 权重。BF16、梯度累积、256x256 数据及调度单位折算属于适配设置，
不能把这一实验等同于论文的 DIV2K 无监督通用融合训练复现。

检查训练循环：A/B 为条件，GT 加噪后参与标准扩散训练，推理没有 GT 输入；RGB 和 [-1,1]
转换一致。验证使用 eval 模式并恢复训练随机状态。验证分片没有补齐重复和 drop_last 丢样。
8卡×每卡1张×累积4次=总 batch32。另以带未使用参数的 CPU/Gloo 模型对相同 no_sync
上下文与全局 batch 梯度进行了对照，最大差约 2.98e-8；这验证累积逻辑，不等于 GPU 位级确定性。
此前 GPU 恢复测试的数据位置、LR、各卡随机状态一致；GPU/BF16 参数存在小量非位级差异。
官方语义编码器有注册但未使用的 Transformer 模板，find_unused_parameters=True 与此一致。

重新检查全部 manifest：train/val/test 的 source_id、scene_group、GT SHA256 跨集合交集均为 0。
训练集 110096 个三元组/6881 个来源；验证和测试各1496个三元组/374个来源。
此前数据构造阶段还完成了全部 PNG checksum/解码和近重复检查；本次未重做全量像素回放。
训练每遍使用110080个样本，丢掉16个以构成整批，随下一遍洗牌变化，影响很小。

原最终评估的 val/test/disk/wide 分别有1496/1496/374/374个唯一ID，
每组清单ID、指标ID、输出PNG文件名集合一致。Lytro/MFFW共33对原尺寸输出，无GT数值指标。
重新加载best和last，以原设置复测固定64张验证图，PSNR/SSIM/Laplacian误差均与历史记录完全相同。
因此目前没有发现“加载错权重”“指标错配”“漏评/重复评”“测试GT泄漏”等问题的证据。

3. 定量结果
===========
同一完整验证集1496张，同一官方5步MFF采样与RGB uint8指标：
                        PSNR       SSIM       Laplacian MAE（低更好）
源图平均                31.7018    0.934980   0.035104
best，第9000步          22.1083    0.852581   0.037764
last，第31247步         19.2363    0.888169   0.020784

best完整测试集：21.5886 dB / 0.848472；源图平均：31.9754 dB / 0.936149。
1496张测试图中，仅98张的融合PSNR超过源图平均。当前差距约10.39 dB，不能视为正常的已就绪基线。
均值融合本身在散焦细节上并不理想；它只是最低限度的简单参考，超过它也不代表达到先进水平。

best根据固定64个来源的验证PSNR选择，选到第9000步；不是最后一步，也不是测试集选择。
监控子集SSIM峰值在27500步，但该步模型权重未单独保留，只有指标和少量预览。
last在完整验证集的SSIM、Laplacian误差优于best，PSNR反而低2.87 dB。
这说明后期并非所有能力都在恶化，仅保留best-PSNR和last掩盖了不同指标间的取舍。
Laplacian MAE是诊断指标，单独变好不足以证明所有真实纹理被恢复；需要放大图共同判断。

原OOD：disk 21.4471 dB；wide 21.4523 dB。
与相同374个内容、相同GT/布局的ID v01配对比较，ID为21.5057 dB，
disk/wide分别下降0.0586/0.0534 dB。不能把全体1496张ID均值直接当配对基准，
也不能凭下降小便宣称鲁棒性好，因为目前颜色误差占据主要误差量。

4. 额外诊断（只使用固定64张验证图，不替换正式基线结果）
====================================================
设置                         best PSNR     last PSNR
官方5步，BF16，seed3407       22.1785       19.0934
官方5步，FP32，seed3407       22.1945       19.1829
官方20步，BF16，seed3407      22.8870       21.0044
官方5步，BF16，seed2026       22.2438       20.4543
同一5步原始输出改固定逆归一化 16.5500       20.1729

FP32仅改变推理精度，不能解释10 dB左右差距；没有做FP32重训，所以没有排除训练精度的影响。
20步能改善结构和部分PSNR，但仍明显低于源图平均31.6998 dB；不能只靠多采样步骤解决。
last对这两个采样种子的PSNR差异约1.36 dB。这里只测两个种子，不是完整方差估计。
直接删除min–max并用(x+1)/2对best反而更差。不能把官方trick简单认定为应删除的bug。
官方索引偏移、终点alpha、MFF非对称裁剪、eta=1在这些采样实验中均保留；本次未对它们
逐项做消融，所以没有证据认定其中任意一项就是主要病因。

最明显的问题是整体色调偏移：对每张图，按RGB各通道对误差做“空间均值项+去均值残差项”分解。
各通道均值项占该图MSE的比例，跨64张图平均为best 55.2%、last 90.2%。
last平均每通道绝对均值偏移约0.09765（像素范围0到1），约24.9/255。
这是逐图比例的平均，不是把所有像素合并后再算的总比例，也不单指一个灰度亮度偏移。
真实Lytro golf等图可见明显黄绿偏色；合成预览中可见结构较清晰但色调偏移。

仅用于归因的GT oracle：利用GT为每张输出的每个RGB通道拟合一个增益和偏置，
last可达到35.2301 dB / 0.971796，best为31.0687 dB / 0.929460。
这使用了GT，不能推理部署、不能写成正式性能，也不是已实现的方法；
它支持“后期保留了相当多的结构信息，但颜色/亮度校准严重失准”的判断。

5. 尚不能判定或需要改进的环节
============================
没有通过这次审计证明现象由某一损失、GroupNorm、采样步偏移或某个模块单独导致。
原color loss作用于[-1,1]图像的方向，exposure loss权重为0，训练/推理裁剪范围不同，
都值得后续独立验证；不能忘记image MSE/SSIM仍然提供亮度监督，也不能直接把这些设定判错。
尚未做同设置训练/验证误差分组与严格小样本过拟合试验，不能仅凭PSNR波动断言过拟合。
本轮采用一组训练seed、有限训练预算，尚无收敛与多seed稳定性证据。

两个工程记录问题：status.json仍停留在31225步且status=running，实际已结束；
应以completion.json（31247步）和job_status.json（complete）为准。REPORT的最后日志步
也不是最终checkpoint步。该问题影响状态显示，不影响模型更新或本次评估。
checkpoint_verification.json还是昨晚第500步的检查记录，不应被误当成最终模型审计。
当前只保留best-PSNR/last，后续应增加少量周期权重以及best-SSIM/细节指标的记录。

6. 建议的决策
============
可以继续使用这套代码做工程开发、诊断、加载已有模型和后续受控试验。
不能把当前21.59 dB的结果直接定为已充分训练的正式MFIF基线，再把修正基础偏色算作研究模块收益。
也没有必要因这一轮结果直接放弃Mask-DiFuser：条件融合已能保留双源结构，后期细节指标在改善。

下一步先做小样本过拟合和按时间步拆解的x0重建/采样诊断，定位训练阶段还是生成阶段产生偏色；
再在独立实验中检查合理的学习率收尾及单变量设置，保留官方配置作为对照。
明确训练预算、输出协议、验证选择标准，确认能稳定超过简单平均并在真实数据上保持颜色与细节后，
再开展源信息参与采样、细节补偿等研究模块的正式消融。当前不宜直接追加模块并宣称有效。
